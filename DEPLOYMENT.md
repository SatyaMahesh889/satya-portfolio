# Deployment: Cloudflare Pages

This site is a static build, deployed as its own Cloudflare Pages project (`satyamahesh-portfolio`). It is independent of the separately hosted project websites it links to. Deploying it does not change them.

## 1. Build settings

| Setting | Value |
| --- | --- |
| Framework preset | Vite |
| Production branch | `main` |
| Root directory | `/` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Node version | Set the environment variable `NODE_VERSION=22.23.3` (matches `.nvmrc`; must be 22.22.2 or newer) |

Cloudflare installs dependencies from `package-lock.json` before running the build command. No backend, database, secrets or paid add-ons are needed.

## 2. Option A: Git integration (recommended)

1. Push this folder to its GitHub repository.
2. Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git**.
3. Select the repository and enter the build settings above.
4. Add `NODE_VERSION=22.23.3` and `VITE_SITE_URL` (see step 4) for **Production**, and for **Preview** if you want them there too.
5. **Save and Deploy**. Every push to the main branch redeploys; pull requests get preview URLs.

## 3. Option B: Direct upload with Wrangler

```bash
npm run build
npx wrangler login
npx wrangler pages project create satyamahesh-portfolio   # first time only
npx wrangler pages deploy dist --project-name satyamahesh-portfolio
```

Remember to set `VITE_*` variables in your shell or `.env` **before** `npm run build`, because they are baked in at build time.

## 4. Environment variables

All optional, all public (they end up in client JavaScript). Never put secrets in `VITE_*` variables.

| Variable | Effect |
| --- | --- |
| `VITE_SITE_URL` | The production origin, without a trailing slash. Use `https://satyamahesh-portfolio.pages.dev` at first, and switch to the custom domain once one is connected. Enables canonical links, `og:url`, absolute OG images, JSON-LD `url`, and `sitemap.xml`. |
| `VITE_CONTACT_EMAIL` | Overrides the default public email (maheshindugula@gmail.com) |
| `VITE_WHATSAPP_NUMBER` | Digits only, e.g. `919876543210`. Shows a WhatsApp card. |
| `VITE_RESUME_URL` | `/resume/<file>.pdf` (place the PDF in `public/resume/`) or an absolute URL. Shows the download button. |
| `VITE_FORM_ENDPOINT` | JSON POST endpoint (Formspree, Web3Forms, or your own Worker). Renders the enquiry form. Success is shown only on a 2xx response. |

After changing variables, trigger a new deployment (they are read at build time).

## 5. Routing

- `/` → `index.html`
- `/projects/<slug>` (four case studies: three websites and ismool) → `projects/<slug>.html`, generated by `scripts/postbuild.ts` with route-specific title, description and Open Graph tags. Cloudflare Pages serves `.html` files at extensionless URLs.
- Any other path → `404.html` with a real **404** status (Pages uses a top-level `404.html` automatically). The React app renders the "Page not found" screen.
- Section links use hashes (`/#contact`), so no extra rewrites are needed and no `_redirects` file is required.

`public/_headers` adds security headers and long-term caching for hashed `/assets/*`.

## 6. Custom domain

1. Pages project → **Custom domains → Set up a custom domain**.
2. Enter the domain (e.g. `satyamahesh.dev` or `www.satyamahesh.dev`).
   - If the domain's DNS is on Cloudflare, the record is created automatically.
   - Otherwise add the CNAME shown (`<project>.pages.dev`) at your DNS provider.
3. Set `VITE_SITE_URL` to the final origin and redeploy so canonical URLs and the sitemap use it.
4. Optional: add a redirect rule from `www` to the apex (or the other way round) under **Rules → Redirect Rules**.
5. Submit `https://<domain>/sitemap.xml` in Google Search Console.

## 7. Post-deploy checks

- Open `/`, `/projects/dsr-charitable-hospitals`, and a nonsense URL (should show 404).
- Toggle the theme, open the mobile menu, follow external links.
- Paste the URL into a link-preview tool (LinkedIn Post Inspector) to confirm the OG image.
- Run Lighthouse against the live URL.
